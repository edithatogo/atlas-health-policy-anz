# Strict testing and static-analysis checkpoint

Existing tracks: T00 (CI and dependencies), T06 (comparison assurance), T07 (deterministic workflows). No new Conductor tracks or medallion promotions.

## Scope

Make strict configuration executable rather than nominal. The earlier green workflows did not execute Ruff or the type checkers. A previously passing test suite does not imply strict static-analysis qualification.

Use pytest 9 strict mode, warnings as errors, unexpected-pass and duplicate-parametrization rejection, explicit plugin loading, offline-by-default Python sockets, bounded timeouts and reproducible random/Hypothesis seeds. The canonical complete suite remains authoritative; picked/testmon are developer acceleration only. Hypothesis profiles do not globally suppress health checks. Test expectations and snapshots are never automatically regenerated by CI.

Ruff selects ALL rules including preview, forbids unsafe auto-fixes and checks formatting. Retain only the existing four global formatting/license/docstring exceptions and documented test-assertion/docstring/literal and CLI-print exceptions. Remove the broad test-annotation exemption. basedpyright uses strict mode, warns-as-errors, rejects missing stubs, Any and unqualified ignores. ty uses all rules at error severity and ignores no generic type-ignore comments. Checks cover src, scripts and tests, with no grandfathered baseline or continue-on-error.

## Dependency selection

Core additions: pytest-mock (autospec), pytest-socket (network isolation), pytest-subprocess (external-tool failure simulation), pytest-httpserver (loopback protocol testing), and inline-snapshot (reviewed source-visible expectations). Existing pytest-cov, timeout, xdist, randomly and Hypothesis remain; property now runs actual generated invariants rather than relabelled unit tests. pytest-benchmark is isolated in test-performance. Existing gremlins/mutmut provide independently runnable targeted mutation methods, never votes establishing clinical correctness.

Newest verified stable additions as observed on 2026-09-05: pytest-socket 0.8.1, pytest-mock 3.15.1, pytest-subprocess 1.6.0, pytest-httpserver 1.1.5, inline-snapshot 0.35.4 and pytest-benchmark 5.3.0. Exact resolver results belong in uv.lock and quality/resolved-test-tools.json, not a hand-written lock. basedpyright's verified current documentation is 1.39.9. No claim that a dependency minimum is the selected installed version.

The same stable package set is checked in both serial coverage and two-worker isolation lanes. Prerelease packages are evaluated only in a disposable, read-only scheduled/manual workflow; it retains the experimental lock without committing or publishing it. Its result is not a release qualification. Existing shared Renovate policy remains intact.

## Deliberate exclusions

Do not add overlapping HTTP mocking packages when the implementation uses urllib; pytest-httpserver covers the actual protocol boundary. Do not add asyncio/Trio/browser/database plugins before corresponding code exists. Do not add retry-until-green plugins, VCR recordings of sensitive material, or a second snapshot format without a concrete gap. New native/Rust pytest replacements remain experiments until plugin and result parity is shown. Python socket interception is not an operating-system sandbox and cannot guarantee subprocess isolation.
